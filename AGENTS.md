# LiteMail — project notes for agents

## Rule: mistakes go on disk

Every trap we hit must be written down here: what went wrong, the right way, and the excuse
not to use again. Global (tool / machine) lessons go to `~/AGENTS.md`. Changing code or
layout without updating this file means the lesson is lost.

## Layout and commands

- `core/` Rust (sync, storage, MIME, SMTP, i18n), exported to Swift with UniFFI 0.32.
- `app/` SwiftUI (macOS 26+). `app/Sources/LiteMailCore/litemail_core.swift` and
  `app/Frameworks/litemail_coreFFI.xcframework` are generated by `scripts/build-core.sh`;
  never edit them by hand.
- Build: `scripts/build-app.sh [--install]`. Test: `scripts/test.sh`.
- Rust is in `/opt/homebrew/opt/rustup/bin` (keg-only): `export PATH="/opt/homebrew/opt/rustup/bin:$PATH"`.
- UI strings: English in code, translations in `app/Resources/zh-Hans.lproj/Localizable.strings`.
  Check coverage with `python3 Tools/extract-strings.py --missing app/Resources/zh-Hans.lproj/Localizable.strings`.
  Core strings use `t!("English", "中文")` (`core/src/i18n.rs`).
- Design: Claude Design project "LiteMail 轻量邮件客户端", file `LiteMail Claude Style.dc.html`.

## Lessons

### async-imap response streams lie on EOF and NO
Wrong: using `session.uid_search / uid_fetch / uid_store / list / select`. Their streams end
quietly on EOF and ignore the tagged status, so a dropped connection during `UID SEARCH`
looked like "mailbox is empty" (the sync then deleted every local copy) and a failed STORE
looked like success (queued user actions were lost).
Right: everything goes through `imap::exec`, which only succeeds on a tagged OK and treats
EOF/BYE as a connection error. Never call async-imap's command helpers in sync code
(login, capabilities, append and IDLE are fine).

### Temporary server errors are not wrong passwords
`[UNAVAILABLE]`, `[INUSE]`, "too many simultaneous connections" on LOGIN are transient. Treat
them as network errors (retry) — classifying them as auth failures stops syncing until the
user re-enters a password. See `imap::is_temporary_login_failure`.

### Dovecot test server on macOS (Tools/testserver)
- `default_vsz_limit = unlimited` fails: macOS RLIM_INFINITY is 2^63-1, Dovecot passes 2^64-1 → use `1T`.
- Dovecot 2.4.5 drops TLS sessions right after login (post-login proxy). Dovecot serves
  plaintext; `tls_front.py` provides IMAPS (31993) and STARTTLS (31144).
- Unix socket paths are limited to 104 bytes: keep the server root short (`.testserver/`).
- Wait for every Dovecot process to exit before wiping its directory, or the new instance
  fights the old one over sockets (`[UNAVAILABLE] Internal error`).
- `set -o pipefail` + `nc … | grep -q` fails because grep exits early and nc gets SIGPIPE.
  Capture output in a variable first.

### Passwords: keychain + stable signing — never a plain file (user decision, 2026-10-19)
What went wrong, in order:
1. Ad-hoc builds. The keychain trusts a cdhash, so every rebuild was a "new app"; reads failed
   and the user had to sign in again after every update.
2. Developer ID signing fixed new items, but the item written by an old ad-hoc build still
   raised **two** dialogs per launch (access list + team partition), and "Allow" lasts one read.
3. I answered with "click Always Allow" — not acceptable.
4. I then moved passwords to a 0600 file. **Wrong**: any program running as the user can read
   it. The user forbade it: passwords must not be readable by other programs.
Right: the login keychain, items named `<install_id>-password-<id>`, always written by the
Developer-ID-signed app (`build-app.sh` picks the identity; requirement = bundle id + team ID). Such items are read by every later signed build with no prompt (verified: add →
relaunch → rebuild with a new cdhash → relaunch, no dialog), and any other program needs the
user's Mac password. `Keychain::set` deletes + re-adds so the access list is the current app's;
reads are serialized by the cache mutex so concurrent readers can't stack prompts.
`secrets::import_password_file` moves the plain file of one early build into the keychain and deletes it.
Never store a password in a file; never ship keychain writes from an ad-hoc build to the user;
never answer a prompt complaint with "click Always Allow" — find out who wrote the item.
Tests: `LITEMAIL_TEST_SECRETS_FILE` (throwaway test passwords only) keeps tests off the keychain;
keychain checks use a scratch data dir and delete their items
(`security delete-generic-password -s uk.icoco.LiteMail -a <prefix>-password-N`).

### Seeing the UI without screen-recording permission
`screencapture` returns nothing without permission and computer use needs the user to
approve. Use the app's own automation channel (`LITEMAIL_AUTOMATION`, `Tools/ui.sh`): it
captures its own windows with `CGWindowListCreateImage`, which needs no permission.

### SwiftUI traps we hit
- `NSApp.sendAction("showSettingsWindow:")` does nothing for SwiftUI `Settings`; use `@Environment(\.openSettings)`.
- A `@State var body` collides with `View.body`; a type named `Group` shadows `SwiftUI.Group`.
- `Button(cond ? "A" : "B")` is a plain `String` — not localized. Use `String(localized:)` per branch.
- `LabeledContent(value: "…")` takes a String: wrap it in `String(localized:)`.
- Interpolating a `String` gives a `%@` key even when it looks numeric (`Sizes.count(...)`).

### Fonts
Claude's own typefaces (Anthropic Sans / Serif) are proprietary — don't bundle them.
We ship Source Serif 4 (SIL OFL). WebKit's content process can't see fonts the app
registers, so the reading pane loads them through `litemail-asset://` (AssetSchemeHandler),
which must send `Access-Control-Allow-Origin: *` or the font is blocked.

### Rust macros
`#[macro_export] macro_rules! t` is only visible by bare name in modules declared after
`#[macro_use] pub mod i18n;` — keep that line first in `lib.rs`.

### App icon
The icon is drawn in code by `Tools/make-icon.swift` (stamped letter, chosen 2026-10-19 after
several rejected rounds); `build-app.sh` renders it. Check every change at 16/32/64 px on light
and dark backgrounds before installing.
Trap: a Write that fails ("modified since read") in the same batch as the render command
leaves the old drawing in place, and the render shows the old icon. Look at the tool results
before judging the picture.

### Duplicate app in Launchpad
Wrong: building to `build/LiteMail.app`. Spotlight indexed it and Launchpad showed two
LiteMail icons (build copy + `~/Applications`). Right: the build output lives in
`build/app.noindex/` (Spotlight skips `.noindex` folders) and `build-app.sh` unregisters it
from LaunchServices. Check with `lsregister -dump | grep 'path:.*LiteMail'` — only the
installed copy should appear.

### Pasted passwords carry line breaks
Wrong: passing the password field straight to IMAP LOGIN. A pasted app-specific password had a
trailing `\n`; async-imap refused it with the raw "validate: invalid character in input" and we
showed that text (as a *network* error, so it was even retried). Right: `MailCore::clean_password`
drops control characters and edge spaces on every entry point (verify, add, update password),
and `E::Validate` maps to a readable auth message. Never show a library's raw error string in the UI.

### Main window review (2026-10-19): what was wrong and the rules now
- **Counts come from the store.** The list header counted unread in the loaded *page* and added
  "+", so it disagreed with the sidebar ("18+" vs 18). Use `counts` / `folder.unread` /
  `folder.total`; unread only for inbox and custom folders, a message count elsewhere.
- **Sync events throttle, typing debounces.** `scheduleReload` cancelled the pending reload on
  every `MessagesChanged`; a long sync reports every few ms, so the list never reloaded and
  showed "Syncing" over thousands of local messages. A pending sync reload is now kept.
- **Sidebar selection colour comes from the asset catalog**, not `.tint`: `AccentColor` in
  `app/Resources/Assets.xcassets`, compiled by `actool` in `build-app.sh`, named by
  `NSAccentColorName`. Check with `Tools/ui.sh dump` (`accent=0.85,0.47,0.34`).
- **Blocked remote images**: rewrite them (`mime::placeholder_remote_images`) — sized ones become
  a soft box, the rest are hidden. Otherwise WebKit draws a broken-image frame with alt text.
- **Designed emails** sit on a card coloured like the email's outer background
  (`mime::outer_background`), so there is no grey-inside-white frame in dark mode.
- **Apple Notes' "Notes" mailbox is not mail** (`imap::is_notes_store`).
- **No pinned Section headers in the message list** (macOS draws them on a grey band); day
  labels are plain rows. Rows under a day label show the time, never "Yesterday" again.
- **A `safeAreaInset` footer needs an opaque background**, or a long sidebar scrolls through it.
- **An empty state must fill its column** (`.frame(maxWidth: .infinity, maxHeight: .infinity)`),
  or the header inset floats to the middle.
- **Screenshots of the test app are always the inactive window** (grey selection): a process
  started from the shell can't activate itself, not even with `open` or
  `activate(ignoringOtherApps:)`. Judge selection colour from the `dump` accent value; don't keep
  retrying activation. Snapshot right after `appearance` switches can catch the toolbar mid-fade:
  wait ~3 s.

### Automation `wait` is in seconds
It used to be milliseconds (`wait 3` = 3 ms), so "dump right after wait 3" looked like the list
never loading and sent me hunting a non-bug in the reload throttle. Now `wait 2` / `wait 0.5`
are seconds. `dump` also prints `pending=` (a reload is scheduled).

### Flaky integration start (seen once, 2026-10-19)
Running `scripts/test.sh` right after a manual `run.sh start` and killing a test app with open
IDLE connections failed 3 tests at LOGIN; two clean reruns passed. If it recurs, look at
`run.sh stop` waiting for Dovecot to exit before the directory is wiped.

### Refresh looked broken (2026-10-19)
Wrong: a manual or periodic sync on an open connection never changed `SyncPhase` unless more than
20 messages arrived, so clicking refresh did nothing visible; the only spinner (while logging
in) sat in the account header right where the section's collapse chevron appears.
Right: every full or manual run reports `SyncPhase::Checking`; the sidebar's bottom `StatusBar`
is the single place for activity ("Checking for new mail…", "Downloading N of M" with a thin
progress line, "Updated just now") and holds the refresh button, which spins while busy.
`AppModel.syncNow` holds "Checking" for ≥0.9 s (`refreshNudge`) so a fast server still shows
feedback — for the button and ⇧⌘N alike. Account headers show only problems, next to the name.
The log records `sync done in N s`.

### Server search: find old mail without keeping it (2026-10-19)
Mail older than an account's window is searched on the server (`MailCore::search_server`,
`server_search.rs`): `UID SEARCH … BEFORE <window start>` (Gmail: `X-GM-RAW`), headers only,
newest 40 per folder / 80 total. Hits have negative ids; `MailCore::read_raw` downloads the body
on first open into a 40 MB in-memory cache — never the store, never disk. Rules:
- Window start comes from `sync::window_start`, shared with the sync's SINCE, so no gap/overlap.
- Non-ASCII terms must be IMAP literals (`imap::exec_segments`, waits for "+"); quoted UTF-8 is
  rejected by many servers.
- Open with EXAMINE + BODY.PEEK so reading doesn't mark mail read on the server.
- Server hits are read-only in the UI (archive/delete/flag/move filtered out by `id > 0`);
  reply, forward, attachments and View Source work through `read_raw`.
- Opening a hit is a network call: `AppModel.loadDetail` runs it off the main thread.

### Sidebar fold arrow did nothing; unread dot outside the row (2026-10-19)
- `Section(isExpanded:)` with a binding computed from `@AppStorage` showed a chevron that didn't
  respond to clicks here. Account headers are now plain rows with our own `AccountHeader`
  button (whole header toggles, chevron rotates, unread count while folded); state stays in
  `collapsedAccounts`; a selected folder of a folded account falls back to All Inboxes.
- The unread dot was pushed into a negative-padding gutter, so it sat outside the selection
  highlight and looked stray. It is now a 7 pt dot just before the time, inside the row.
- Never ship a control we haven't seen respond: test it (automation `fold <accountId>`).

### Send-from addresses (aliases) and Sent-list avatars (2026-10-19)
IMAP never tells a client which other addresses an account owns, so "From" only offered the
login address. Now `MailCore::send_addresses` = main address + user-added aliases (`aliases`
table, schema v4) + found ones: From addresses in the Sent folder (the server only accepts
senders the account owns, so they're proven) and, for iCloud @me.com / @mac.com, the @icloud.com
twin. `Draft.from` carries the chosen alias into the From header and the SMTP envelope; replies
answer from the address the message was sent to and reply-all never copies the user's own
addresses. Don't guess other variants (an @icloud.com account has no guaranteed @me.com).
Rows in Sent/Drafts show the first recipient's avatar and name, never the user's own.
